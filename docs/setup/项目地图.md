## 1. 一句话定位

FalconX 是 B-Book 模式 CFD 交易平台（GODSA 架构）：**客户端交易终端**（`falconx-frontend`）+ **5 后端微服务 + 网关**（identity/market/trading-core/wallet/gateway）+ **管理端**（`falconx-console-service` 后端 + `falconx-console-frontend` 前端）。技术栈 Java 25 / Spring Boot 4 / MyBatis Plus + XML / MySQL 8.4 / Redis / Kafka / ClickHouse / Flyway；前端 Vite + React + TS + Zustand + React Query。

## 3. 架构总览

### 3.1 服务与端口（一期固定 5 服务 + 网关）

| 服务 | 端口 | MySQL DB | 职责 |
|------|------|----------|------|
| `falconx-gateway` | 18080 | — | WebFlux 网关；JWT 验证；限流；Resilience4j 熔断；WS 代理 |
| `falconx-identity-service` | 18081 | `falconx_identity` | 注册/登录；RSA JWT；BCrypt；KYC；用户资料 |
| `falconx-market-service` | 18082 | `falconx_market` + ClickHouse | LP 自建行情；K 线聚合；FX 汇率；交易日历；组加点 |
| `falconx-trading-core-service` | 18083 | `falconx_trading` | 账户/账本；订单/持仓；存款；风控；强平；多币种；CROSS/ISOLATED |
| `falconx-wallet-service` | 18084 | `falconx_wallet` | 链上地址分配；ETH/TRON 多链监听；存款确认 |
| `falconx-frontend`（客户端） | 5173 / dev 5200 | — | React 交易终端 |
| `falconx-console-service`（管理端后端） | 18085 | `falconx_console` | RBAC；客户/交易/风控/对账/通知运营；透传下游 internal RPC |
| `falconx-console-frontend`（管理端前端） | dev 5300 | — | AntD 5 管理后台 |

基础设施端口：MySQL 3306 / Redis 6380(host) / Kafka 9092 / ClickHouse 8123(HTTP)·9000(native)。

### 3.2 仓库顶层模块

- **服务**：`falconx-{gateway,identity-service,market-service,trading-core-service,wallet-service,console-service}`
- **前端**：`falconx-frontend`（客户端）、`falconx-console-frontend`（管理端）
- **共享**：`falconx-common`（ApiResponse/ErrorCode）、`falconx-domain`（枚举/DomainEvent）、`falconx-infrastructure`（Snowflake/TraceId/Kafka 支撑/RSA）
- **契约（禁业务逻辑）**：`falconx-{identity,market,trading,wallet}-contract`
- **运维**：`falconx-canary`（金丝雀）、`deploy/`（nginx-edge + docker-compose.prod）、`scripts/`（起停/部署脚本）、`tools/`（tier-seed 等）

### 3.3 每服务标准包结构

根包 `com.falconx.{service}`：`controller / command / application / service / entity / repository(+mapper) / config / error / consumer / producer`。业务查询一律 MyBatis + XML Mapper（禁 Service 层拼 SQL、禁 In-Memory Repository）。

## 4. 接续开发：换机从 GitHub clone 后怎么跑起来

> 完整细节见 [开发启动手册](开发启动手册.md) / [服务本地启动指南](服务本地启动指南.md) / [本地基础设施启动说明](本地基础设施启动说明.md)。以下是最短路径。

1. **环境要求**：JDK 25、Maven、Node ≥ 20、Docker（WSL2 见 §5.2）。
2. **基础设施**：`docker compose up -d`（起 MySQL/Redis/Kafka/ClickHouse 4 容器）。
3. **机密配置**：本私有仓库**已直接提交 `.env` + `tools/*-truststore.p12`**（commit `c95ca5a8`，为多机同步）——所以 clone 后**通常已带可用 `.env`，无需手工配置**，[`.env.example`](../../.env.example) 仅作键名参考 / 新环境模板。
   - 仅调 identity/gateway/trading-core + 前端时，连 LP/wallet 机密都不需要——它们走 `dev` profile 的本地默认（DB root/root、本地 RSA dev 密钥），可独立起栈。
   - ⚠️ 安全提示：把真实机密提交进仓库是「便利 > 严格」的取舍，仅因本仓库私有。若要改为机密不入库，需 `git rm --cached .env*` + 各机自备（用 `.env.example` 模板）——由用户决定。
4. **构建 + 起后端**：`mvn -q -DskipTests clean package` 后按 [服务本地启动指南 §2.1] 的启动顺序起 jar；或一键 `bash scripts/local-start.sh`（screen 后台保活 + JVM 堆护栏）。停：`bash scripts/local-stop.sh`。
5. **起前端**：客户端 `cd falconx-frontend && npm i && npm run dev`（:5200，proxy /api→:18080）；管理端 `cd falconx-console-frontend && npm i && npm run dev`（:5300，proxy /admin→:18085）。
6. **Flyway**：各服务启动时自动迁移 schema，无需手工建表。**核对两边版本**用 `SELECT version FROM flyway_schema_history`。
   - ⚠️ 本地 dev `falconx_trading` 历史上有 STAGE-14B 漂移态（boot 撞 Duplicate column）；跑 trading-core `@SpringBootTest` 用干净 IT 库 `falconx_trading_it`。新环境干净 clone 不受此影响（迁移按 V1→最新顺跑）。
7. **前端验证三件套**（提交前）：`npm run test`、`npm run lint`、`npm run build`。

**跨机一致性保证**：代码 + Flyway 迁移 + seed（symbols/交易时段/tier/console 超管自举）+ `.env` + truststore 全在（私有）仓库，新机干净 clone 起栈即得到与 demo 一致的 schema、基础数据与机密配置；业务运行数据（持仓/订单/客户）各环境独立、不随仓库同步（见 [冷启动完备性矩阵 部署手册 §0.6]）。

## 5. demo 演示档 + 运维要点（详见 [部署手册 §0]）

- **地址**：客户端 `https://app-falconx.lifebyteapp.dev/`、管理端 `https://admin-falconx.lifebyteapp.dev/`。服务器 `ubuntu@10.143.170.189`。
- **部署命令**：`bash scripts/deploy-to-server.sh`（全量）/ `-s client-frontend,console-service,...`（指定服务）；`--skip-mvn`（前端改动免重打 jar）。脚本自动 mvn package(skip test) → docker build(linux/amd64) → save → scp → `up -d --force-recreate` → 重启 edge → 公网烟雾。
- **同步约定**：代码 + Flyway schema 同步；**data / `.env` secret 不同步**（服务器有真实演示数据与真 secret）。
- **运维红线（血泪教训）**：
  - 手动重启后端**一律 `up -d --force-recreate`，不用 `restart`**（restart 会产僵尸容器：context 关闭但 JVM 存活，容器 running/RestartCount=0 却不服务 → gateway 504）。重启后端后必 `restart edge`（IP 缓存）。
  - 验收标准：容器 running / 匿名 401 **都不算数**——必须看日志 `Started XxxApplication` + 带 token 的公网端到端 200。
  - 改了 bean 装配，部署前本地起 jar 验 `Started`（见教训 L1）。
- **管理端 demo QA 约束**：`/admin/*` API 受 IP 白名单，本地浏览器直连 demo 鉴权会被拦；登录后页面 QA 走本地 dev proxy→demo 后端 或 fetch 伪会话（见教训 **L7**）。客户端 demo 不受白名单，可用真实账号经本地 proxy 验收。

### 5.2 WSL2 本地 Docker 起不来时

本机无 systemd docker.service、无免密 sudo，Docker 靠 Windows Docker Desktop。恢复：启动 Docker Desktop → 若 `/var/run/docker.sock` 不出现，用 `wsl.exe -d <distro> -u root` 把 `/mnt/wsl/docker-desktop/shared-sockets/.../docker.proxy.sock` `chmod 666` 并 symlink 到 `/var/run/docker.sock`（Docker Desktop 重启后需重做）。详见 [部署手册](AWS演示档部署手册.md) 与历史记录。
