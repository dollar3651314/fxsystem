# 服务本地启动指南

> 本文件记录在本地开发环境中启动 FalconX 各服务的**已验证命令**与关键陷阱。
> 基础设施（MySQL/ClickHouse/Redis/Kafka）的 Docker 启动见 [本地基础设施启动说明.md](./本地基础设施启动说明.md)。

## 1. 构建

```bash
# 根目录一次性全量构建（跳过测试）
mvn clean package -DskipTests
```

## 2. 服务启动命令（已验证）

### 2.1 启动顺序（重要）

```
1. identity-service
2. gateway
3. trading-core-service         ← 必须在 market-service 之前启动
4. market-service               ← 必须在 trading-core 注册 Kafka consumer 之后启动
5. wallet-service
6. falconx-frontend
```

**trading-core 必须先于 market-service 启动**的原因：
market-service `stub` 模式在启动时立即发布一批行情到 Kafka Topic。
trading-core 的 Kafka consumer group 使用 `auto-offset-reset: latest`——
如果 trading-core 的 consumer 还未注册，这批行情会被跳过，
导致 trading-core 始终没有报价，下单时返回 `MARKET_QUOTE_NOT_FOUND`。

### 2.2 identity-service

```bash
java -jar falconx-identity-service/target/*.jar --spring.profiles.active=dev
```

**必须传 `--spring.profiles.active=dev`**。不加时 `${FALCONX_IDENTITY_PRIVATE_KEY_PEM}` 占位符不解析，
Base64 解码器收到字面量 `$`（十六进制 0x24），抛出 `Illegal base64 character 24`。

### 2.3 gateway

```bash
java -jar falconx-gateway/target/*.jar --spring.profiles.active=dev
```

**必须传 `--spring.profiles.active=dev`**（同上，RSA 公钥占位符）。
`application-dev.yml` 还覆盖了 Resilience4j TimeLimiter 超时，不加 dev 则默认 1 秒超时，
所有路由在第 1 秒时统一返回 `dependency timeout`。

### 2.4 market-service（真实 LP + ClickHouse 写入）

```bash
java \
  -DFALCONX_MARKET_DB_USERNAME=root \
  -DFALCONX_MARKET_DB_PASSWORD=root \
  -jar falconx-market-service/target/*.jar \
  --falconx.market.analytics.quote-flush-interval=10000
```

**`-D` 系统属性必须放在 `-jar` 之前**。放在 `-jar` 之后会被 Spring Boot 当作应用参数处理，
不会被 JVM 系统属性解析，导致数据源连接串出现字面量 `${FALCONX_MARKET_DB_USERNAME}`，
报错 `Access denied for user '${FALCONX_MARKET_DB_USERNAME}'`。

默认不设置 `stub` profile，market-service 会连接真实 LP，并启用真实 ClickHouse writer。
报价 tick 会先进入内存缓冲队列，ClickHouse `quote_tick` 默认每 10 秒定时批量写入一次；
`quote-batch-size=200` 表示每批 INSERT 的最大记录数，运行时低于 1 会按 1 执行，高于 10000 会按 10000 执行。
`stub` profile 仅用于临时 mock 行情演示；该模式使用日志型 writer，不会真实写 ClickHouse。

### 2.5 trading-core-service

```bash
java -jar falconx-trading-core-service/target/*.jar \
  --falconx.trading.cache.quote-ttl=1d \
  --falconx.trading.stale.max-age=1d
```

本地 dev 下必须覆盖以上两个参数，原因：
- 默认 `quote-ttl`（Redis TTL）和 `stale.max-age`（5 秒）会在 stub 行情发布后很快过期，
  导致每次下单都返回 `MARKET_QUOTE_STALE`。
- 生产环境不需要这两个 override——LP 行情持续推送，不会 stale。

### 2.6 wallet-service

```bash
java \
  -DFALCONX_WALLET_DB_USERNAME=root \
  -DFALCONX_WALLET_DB_PASSWORD=root \
  -jar falconx-wallet-service/target/*.jar
```

同 market-service，`-D` 属性必须放 `-jar` 之前。
wallet-service 会自动读取根目录 `.env`；ERC20 合约键为
`FALCONX_WALLET_ERC20_USDC_CONTRACT` / `FALCONX_WALLET_ERC20_USDT_CONTRACT`，
TRC20 测试 RPC 与 USDT 合约键为 `ALCHEMY_ETHEREUM_NILETEST_HTTPS` /
`FALCONX_WALLET_TRC20_USDT_CONTRACT`。默认链拉取频率为 5 分钟。
`ALCHEMY_ETHEREUM_NILETEST_HTTPS` 必须填写 TRON HTTP API 基础地址，不要追加
`/wallet/...` 路径；wallet-service 会请求 `/wallet/getnowblock`，并通过
`/walletsolidity/gettransactioninfobyblocknum` 读取 TRC20 `Transfer` 日志。
首次启动若 `t_wallet_chain_cursor` 仍为初始游标 `0`，监听器会先把游标基线推进到当前最新块，
不会回扫基线之前的历史入金；基线之后的 TRC20 USDT 入金按 5 分钟频率进入监听。

### 2.7 前端

```bash
cd falconx-frontend && npm run dev
```

默认监听 `http://localhost:5173`。

## 4. 常见陷阱（已踩）

### 4.1 MyBatis XML 中 MySQL NULL-safe 操作符

MySQL `<=>` 在 MyBatis XML mapper 文件中必须写成 `&lt;=>`，否则 SAX 解析器把 `<=>` 识别为标签开头，
抛出 `元素内容必须由格式正确的字符数据` 解析错误。

```xml
<!-- ❌ 错误 -->
WHERE symbol <=> #{symbol}

<!-- ✅ 正确 -->
WHERE symbol &lt;=> #{symbol}
```

### 4.2 Resilience4j TimeLimiter 默认超时

Spring Cloud Gateway 的 `CircuitBreaker` filter 内置 Resilience4j TimeLimiter，默认超时 **1 秒**。
不在 `application-dev.yml` 显式配置时，所有路由在 1 秒后均返回 `dependency timeout`，
与 `connect-timeout-millis` / `response-timeout-millis` 无关。

已在 `falconx-gateway/src/main/resources/application-dev.yml` 固定为 10s：

```yaml
resilience4j:
  timelimiter:
    instances:
      identity-route:
        timeout-duration: 10s
      market-route:
        timeout-duration: 10s
      trading-route:
        timeout-duration: 10s
      wallet-route:
        timeout-duration: 10s
```

### 4.3 clientOrderId 幂等缓存

trading-core 对 `clientOrderId` 做幂等校验并缓存结果（包括拒单结果）。
本地调试时使用同一 `clientOrderId` 重复下单，会直接返回第一次的缓存结果（`duplicate: true`），
看不到新错误的真实原因。

每次调试请使用唯一的 `clientOrderId`（如时间戳）。

### 4.4 stub 模式下的 profile 完整覆盖

market-service `stub` profile 需要以下 4 个仓储实现均存在 Stub 版本：

- `StubMarketLatestQuoteRepository`
- `StubMarketOutboxRepository`
- `StubMarketReferenceQuoteRepository`
- `StubMarketQuoteHistoryRepository`

如新增实现了 `@Profile("!stub")` 注解的仓储，必须同时新增对应 Stub 实现。

## 5. 停止服务

停止应用服务（保留基础设施容器）：

```bash
# 找到各服务的进程
lsof -i :18080  # gateway
lsof -i :18081  # identity-service
lsof -i :18082  # market-service
lsof -i :18083  # trading-core-service
lsof -i :18084  # wallet-service
lsof -i :18085  # console-service
# kill <PID>

# 或者按 jar 关键字搜索
pgrep -fl "falconx" | awk '{print $1}' | xargs kill
```

停止基础设施：

```bash
docker compose stop   # 保留数据，只停容器
# docker compose down  # 停容器并删除网络（不删数据卷）
```
