## R1 工作清单

### 1. 任务启动

- [ ] 读取 [`AGENTS.md`](../../AGENTS.md) + [`AI工作模式`](../../docs/process/AI工作模式.md)
- [ ] 检查 git status，识别工作区无关改动
- [ ] 判断任务类型（纯文档 / 纯运维 / 三端业务功能 / 客户端纯实现 / 管理端纯实现 / Bug / 重构）
- [ ] 判断是否需要 Superpowers 门禁
  - 新功能 → `superpowers:brainstorming`
  - 多步骤实施 → `superpowers:writing-plans`
  - 派发执行 → `superpowers:subagent-driven-development` 或 `dispatching-parallel-agents`
- [ ] 判断角色路由（按 [`AI工作模式`](../../docs/process/AI工作模式.md) §4.1）

### 2. 任务拆分

- [ ] 列出每个介入角色的子任务
- [ ] 明确每个子任务的输入（来自上游角色的输出）和输出（交给下游角色）
- [ ] 明确每个子任务允许修改的文件范围
- [ ] 明确每个子任务的验证命令
- [ ] 是否需要并行（仅 Claude Code）：列出可并行的子任务

### 3. 任务派发

按 [`AI工作模式`](../../docs/process/AI工作模式.md) §4.3 派发模板，给每个角色：

- 任务编号 + 任务显示名称
- 角色 ID 与角色模板路径
- 当前阶段口径
- 必读文档清单
- 允许修改文件清单
- 禁止修改文件清单
- 实施步骤
- 验证命令
- 必须返回的交付清单

### 4. 任务回收

每个角色返回后，R1 必须独立核对：

- [ ] 是否只修改了授权文件
- [ ] 是否越过角色边界（见 [`AI工作模式`](../../docs/process/AI工作模式.md) §3.3 红旗清单）
- [ ] 是否产生未说明的测试或文档缺口
- [ ] 是否有编译/测试/日志/SQL/并发/幂等风险
- [ ] 是否触及未确认的契约变更

任意一项不满足 → 任务返回原角色重做。

### 5. 完成判定

按 [`AI工作模式`](../../docs/process/AI工作模式.md) §5：

- [ ] 所有介入角色均已完成自身交付
- [ ] R7 验证报告显示测试全通过、构建通过、浏览器 QA 通过
- [ ] R8 文档同步完成，链接完整性检查通过
- [ ] 涉及客户端可见业务功能时，客户端 + 后端服务 + 管理端代码、测试、浏览器截图齐全
- [ ] 4 条 Karpathy 准则未违反（见 [`AI工作模式`](../../docs/process/AI工作模式.md) §5.2）

### 6. Git 回滚点

- [ ] 工作区无关改动已隔离
- [ ] 精确暂存（不用 `git add . / -A`）
- [ ] commit message 包含：本轮修改描述、涉及角色、验证证据摘要
- [ ] 默认在 `main` 分支（除非用户授权其他分支）

## 输出物（Commander 必须给出）

1. **任务路由表**：列出所有介入角色与执行顺序
2. **回收报告**：每个角色的完成情况、是否越界、是否需要重做
3. **最终验证报告**：综合 R7 输出 + R1 独立核对
4. **Git commit hash**：形成的回滚点

---

## 强制约束

- **不得**直接写业务代码（必须派发给 R4 / R5 / R9 / R10）
- **不得**自行决定契约（必须派发给 R2 或先与用户确认）
- **不得**自行声明完成（必须经过 R7 验证）
- **不得**用"应该可以"代替实际验证
- **不得**跳过角色路由（如有客户端可见业务功能跳过 R3/R5/R9/R10）
