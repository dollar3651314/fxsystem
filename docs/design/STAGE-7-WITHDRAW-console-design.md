### 2.2 状态徽章

| 状态 | 颜色 | 文案 |
| --- | --- | --- |
| `COOLING` | 灰色 + ⏳ | 冷静期（系统自动转 PENDING） |
| `PENDING` | 橙色 + ⏰ | 待审核 |
| `APPROVED` / `PROCESSING` | 蓝色 | 处理中 |
| `APPROVED_DELAYED` | 紫色 + ⏱ + 倒计时 | 大额延迟 |
| `COMPLETED` | 绿色 + ✅ | 已完成 |
| `FAILED` | 红色 + ❌ | 失败 |
| `CANCELED` | 灰色 + 🚫 | 已取消 |
| `REJECTED` | 红色 + ❌ | 已拒绝 |

### 2.3 列表排序

- 默认 status PENDING 优先（admin 一眼看到待办），再 APPROVED_DELAYED，再按 created_at DESC
- 列点击切换排序：created_at / amount / user_id

- 任一权限缺失：按钮 disabled + tooltip "无此权限"

## §6. 审计

所有 approve / reject / emergency-cancel 操作通过 `OperationAuditAspect` 自动写入 `t_admin_operation_log`：

- `action` = `WITHDRAW_APPROVE / WITHDRAW_REJECT / WITHDRAW_EMERGENCY_CANCEL`
- `target_type` = `WITHDRAW_ORDER`
- `target_id` = `withdrawId`
- `risk_level` = `HIGH`（通过 / 拒绝）/ `CRITICAL`（紧急取消）
- `ip` + `ua` 自动从请求 header 提取
- `params_json` 记录 reviewNote / reason
- `result` = `SUCCESS / FAILED`
