## §0 项目定位

| 维度 | 当前定义 |
|------|---------|
| 产品形态 | **BBook CFD 交易平台**（平台作为用户对手盘，无 A-book 对冲出口） |
| 核心能力 | 注册登录 → 入金 → 行情订阅 → 市价开仓 → 持仓管理 → 手动平仓 / TP / SL / 强平 / Swap 结算 |
| 一期边界 | 仅市价单、仅 ISOLATED + 基础 CROSS、无出金、无 KYC、无管理后台、无邮箱验证、无国别黑名单、无资金密码 |
| 技术栈 | Spring Boot 4 / JDK 25 / MyBatis Plus + XML / Redisson / Kafka / MySQL 8.4 / ClickHouse / Vite + React + TS |

> **用户修改建议**：
> _核心能力增加：爆仓推送、盈亏计算和推送、开平仓手续费、爆仓不收取手续费、爆仓金额不为负数、后端K线生成、盈亏计算、价格监控_
> _一期边界修改：市价单/挂单、仅 ISOLATED 逐仓模式， 只保留CROSS 扩展，暂时不做实现，出金走人工审核，审核通过，在链上完成出金，KYC只需要在出金的时候进行简单的KYC，身份信息，校验格式正确，由人工审核来判断真实性。管理后台也放在一期完成，前期先搭建好管理后台的骨架和前端设计，补齐已完成的任务需要的管理后台的工作，后续工作需要同步完成管理后台的功能开发。_

## §2 身份域（identity-service）

### 2.1 业务目标
注册、登录、Token 管理、用户产品组（symbol 可见性边界）、邮箱可信度事实留痕

### 2.2 核心实体
| 表 | 字段语义 |
|----|---------|
| `t_user` | id, email, password_hash, status(`ACTIVE/PENDING_DEPOSIT`), email_verified, group_code, activated_at |
| `t_refresh_token_session` | jti, user_id, expires_at, revoked_at（一次性轮换） |
| `t_inbox` | event_id, event_type（消费 `trading.deposit.credited` 幂等留痕） |

### 2.3 接口
| 端点 | 描述 |
|------|------|
| `POST /api/v1/auth/register` | 注册返回 `userId/uid/email/status=ACTIVE/emailVerified=false` |
| `POST /api/v1/auth/login` | 登录签发 access + refresh token |
| `POST /api/v1/auth/refresh` | Refresh 一次性轮换（旧 refresh 立即失效）|
| `POST /api/v1/auth/logout` | Access Token 加入 Redis 黑名单 |

### 2.4 关键实现
- 密码：BCrypt 12 轮
- JWT：RSA 私钥签发；payload 含 `sub/uid/email/status/groupCode/iat/exp/jti`
- 邮箱可信度：`email_verified=0` 注册即写入，**当前不阻断任何功能**
- legacy `PENDING_DEPOSIT` 状态：消费入金事件时归一化为 `ACTIVE`

### 2.5 已知缺口
- ❌ 无邮箱验证发送
- ❌ 无国别黑名单
- ❌ 无资金密码
- ❌ 注册后**未**预分配钱包地址（用户进入入金页才 `ensure` 懒分配，待 `WALLET-REGISTER-ADDRESS-01`）

> **修改建议区**（在此填写身份域需要修改的实现逻辑）：
> 无修改

## §3 行情域（market-service）

### 3.1 业务目标
唯一生产报价源接入（自建 LP）、品种治理、行情质量分级、K 线聚合、北向 WebSocket 推送

### 3.2 核心实体
| 表 | 字段语义 |
|----|---------|
| `t_symbol` | symbol, status, max_leverage, market_code, group_visibility |
| `t_symbol_quote_mapping` | platform_symbol → source_symbol，price_multiplier，bid/ask_adjustment，lp_subscribe_enabled |
| `t_symbol_group_visibility` | group_code → 可见 symbols |
| `t_trading_hours / _exception / _holiday` | 交易时段、人工例外、节假日 |
| `t_swap_rate` | symbol → long/short rate（每日 17:00 EST 滚动） |
| `t_outbox` | 行情 outbox（Swap 结算事件） |
| ClickHouse `quote_tick / kline` | 时序数据 |

### 3.3 接口
| 端点 | 描述 |
|------|------|
| `GET /api/v1/market/symbols` | 列出当前用户组可见品种 |
| `GET /api/v1/market/quotes/{symbol}` | 单品种最新价 |
| `GET /api/v1/market/klines/{symbol}` | K 线（1m/5m/15m/1h/4h/1d） |
| WebSocket `ws://{host}/ws/v1/market` | price.tick / kline.{interval} 订阅 |

### 3.4 关键实现
- **LP 接入**：`SocketIoLpMarketQuoteProvider` Socket.IO + app token 加密握手 + serverId=17 + Snappy 解压 + `external-sub-symbol` 字符串订阅
- **行情质量五态**：`FRESH / STALE / NO_QUOTE / MARKET_CLOSED / ABNORMAL`，仅 FRESH 可成交
- **异常检测**：点差过大、单 tick 跳变、短时波动率（`BBOOK-RISK-GUARD-01` 已落地）
- **K 线聚合**：服务内推进窗口，收盘时写入 ClickHouse
- **Swap rate 共享**：market 写入 Redis 快照，trading-core 只读消费
- **stub profile**：仅集成测试用，启动时一次性推送静态价（不模拟行情持续推）

### 3.5 已知缺口
- ❌ 无 LP 历史 K 线回填（停机期数据缺失）
- ❌ 无行情冷启动预热（启动后第一帧到达前下单会拒）
- ❌ 无 LP 长断线自动 SUSPEND
- ❌ 无 K 线聚合多实例 leader 选举（多实例会重复写 ClickHouse）

> **修改建议区**（在此填写行情域需要修改的实现逻辑）：
> _增加：加入LP 长断线自动 SUSPEND_
> _修改：K 线聚合一期不做多示例，由单实例完成_

## §4 交易域（trading-core-service） — **核心业务域**

### 4.1 业务目标
账户与账本、订单与成交、持仓管理、TP/SL、强平（ISOLATED 仓位级 + CROSS 账户级）、Swap 结算、BBook 风控、用户实时推送

### 4.2 核心实体
| 表 | 字段语义 |
|----|---------|
| `t_account` | user_id, currency, balance, frozen, margin_used |
| `t_ledger` | biz_type 枚举（DEPOSIT/TRADE_OPEN/TRADE_CLOSE/REALIZED_PNL/LIQUIDATION_PNL/FUNDING_FEE/SWAP/ISOLATED_MARGIN_SUPPLEMENT 等） |
| `t_deposit` | wallet_tx_id, status, amount（消费 wallet 入金事件） |
| `t_order` | type=MARKET（仅）、status(PENDING/FILLED/REJECTED/...）、margin_mode |
| `t_position` | side, quantity, entry_price, margin, liquidation_price, take_profit_price, stop_loss_price, status(OPEN/CLOSED/LIQUIDATED), close_price, close_reason, realized_pnl, **margin_mode（CROSS=1/ISOLATED=2）**|
| `t_trade` | trade_type(OPEN/CLOSE/LIQUIDATION), price, realized_pnl, fee |
| `t_risk_config` | symbol → max_leverage, max_position_per_user, max_position_total, hedge_threshold_usd |
| `t_risk_exposure` | symbol → long/short/net qty + USD |
| `t_hedge_log` | 敞口超阈值告警留痕（BBook 观测桩） |
| `t_risk_control_action` | type(REJECT_OPEN/REDUCE_ONLY/SUSPEND_SYMBOL/GLOBAL_PAUSE), scope, source, is_active |
| `t_risk_market_config` | 跨品种相关性组（V9 已建表，无默认数据） |
| `t_liquidation_log` | margin_mode, **evidence_json**（V10 新增，CROSS 账户级证据） |

### 4.3 接口

| 端点 | 描述 |
|------|------|
| `GET /api/v1/trading/accounts/me` | 账户余额 |
| `POST /api/v1/trading/orders/market` | 市价开仓（含 marginMode 参数） |
| `POST /api/v1/trading/positions/{id}/close` | 手动平仓（仅全平） |
| `POST /api/v1/trading/positions/{id}/margin` | 追加 ISOLATED 保证金 |
| `PATCH /api/v1/trading/positions/{id}` | 修改 TP/SL |
| `GET /api/v1/trading/orders/trades/positions/ledger/liquidations` | 用户视角查询 |
| `GET /api/v1/trading/swap-settlements` | Swap 结算明细 |
| WebSocket `ws://{host}/ws/v1/trading` | account/order/position/trade/margin/ledger/liquidation/risk-controls 用户推送 |

### 4.4 关键流程

#### 4.4.1 市价开仓
```
DefaultTradingRiskService.evaluateMarketOrder():
  1. symbol 有效 + 交易时间 + 报价 FRESH
  2. 杠杆 ≤ max_leverage
  3. BBook 风控（GLOBAL_PAUSE / SUSPEND_SYMBOL / REJECT_OPEN / REDUCE_ONLY）
  4. CROSS/ISOLATED 模式冲突检查（不允许同账户混用）
  5. 持仓上限（per_user / platform_total）
  6. 跨品种集中度（t_risk_market_config）
  7. 保证金充足（marginAmount + fee ≤ available）
  8. 算 liquidation_price：
     ISOLATED: entry_price ± margin / quantity
     CROSS: 不算单仓强平价（账户级评估）
↓ 通过
TradingOrderPlacementApplicationService:
  事务内：reserve margin (frozen) + chargeFee (balance) + 写 t_order + t_position + t_trade(OPEN) + t_ledger(TRADE_OPEN) + outbox
  事务后：confirmMarginUsed (frozen → margin_used) + 推送 account/position/order WebSocket
```

#### 4.4.2 持仓退出（双轨入口，`CROSS-MARGIN-EXEC-01-A` 重构后）
```
TradingPositionCloseApplicationService:

closePositionByPositionLevelTrigger(id, reason, quote)  ← QuoteDrivenEngine 调用
  ├─ ISOLATED 强平：触发条件 mark <= liquidation_price (LONG) / >= (SHORT)
  ├─ TP：mark >= take_profit_price (LONG) / <= (SHORT)
  ├─ SL：mark <= stop_loss_price (LONG) / >= (SHORT)
  └─ 调用 PositionTriggerRuleEvaluator 二次校验，evidence_json = null

closePositionByAccountLevelLiquidation(id, quote, evidence)  ← CrossMarginLiquidationApplicationService 调用
  ├─ CROSS 账户级强平：equity = balance + Σ unrealizedPnl ≤ Σ (entry × qty × maintenance_rate)
  ├─ 选亏损最大的 CROSS 持仓平仓
  └─ evidence 序列化为 JSON 落 t_liquidation_log.evidence_json

closePosition(command)  ← 用户手动平仓
  └─ 全平，evidence_json = null

settlePositionExit() 共享流程：
  事务内：releasePositionMargin → 写 t_trade(CLOSE/LIQUIDATION) → 更 t_position 终态 →
         t_ledger(REALIZED_PNL/LIQUIDATION_PNL) → 负净值兜底 platform_covered_loss → outbox →
         (强平时) t_liquidation_log
  事务后：移除 OpenPositionSnapshot 内存视图 + WebSocket 推送
```

#### 4.4.3 行情驱动引擎（QuoteDrivenEngine）
```
每个 Kafka tick:
  1. 写 Redis 最新价 + 行情质量校验
  2. 找出该 symbol 所有 OPEN 持仓（OpenPositionSnapshotStore 内存视图）
  3. 对每个 ISOLATED/CROSS 持仓：
     - PositionTriggerRuleEvaluator 评估 TP/SL/ISOLATED 强平
     - 命中 → closePositionByPositionLevelTrigger
  4. 对涉及的 CROSS 用户：
     - CrossMarginLiquidationApplicationService.evaluateAndLiquidate(userId, snapshot)
     - 触发 → closePositionByAccountLevelLiquidation（每 tick 最多平 1 笔）
  5. 刷新 t_risk_exposure（敞口实时观测）
```

#### 4.4.4 BBook 风控闭环（`BBOOK-RISK-CONTROL-01` 已完成）
```
DefaultTradingRiskObservabilityService.observeThreshold():
  敞口超阈值 → 自动激活 REJECT_OPEN（来源=THRESHOLD_BREACH）
  敞口回落 → 自动停用

DefaultTradingRiskObservabilityService.checkConcentration():
  跨品种集中度组超阈值 → 自动激活（依赖 t_risk_market_config 默认数据，当前未注入）

风控动作四级：
  REJECT_OPEN < REDUCE_ONLY < SUSPEND_SYMBOL < GLOBAL_PAUSE（按严重度升序）

每次开仓前置：findMostSevereActiveBySymbol → 阻断
全局检查：hasActiveGlobalPause → 阻断所有
```

### 4.5 已知缺口与临时方案

| 项 | 状态 |
|----|------|
| 限价单 / 止损单 | ❌ 仅 MARKET，PENDING/TRIGGERED 状态枚举已预留未用 |
| 部分平仓 | ❌ 仅全平，无 t_partial_close_log |
| CROSS 全场景测试 | ⚠️ 当前 6 个用例（基础范围），跨品种/CROSS+ISOLATED 混合/SL 等待补（执行路径阶段 1.2） |
| 用户实时推送 CROSS 字段 | ⚠️ account.update payload 缺 marginMode/equity/crossMaintenance（执行路径阶段 1.3） |
| `OpenPositionSnapshotStore` | ⚠️ 单实例 ConcurrentHashMap，多实例需 Kafka 增量同步（执行路径阶段 4.4） |
| 用户实时推送 | ⚠️ best-effort 单实例，多实例需 Kafka 广播（阶段 4.1） |
| 跨品种集中度数据 | ⚠️ V9 表已建，默认相关性组未注入（阶段 3.3） |
| 风控运营接口 | ❌ 一期不提供管理端，运营只能 SQL 操作 `t_risk_control_action`（阶段 3.1） |
| `TradingHedgeAlertEvent` | ⚠️ Spring 进程内事件，非真正告警 sink |
| 资金费率（funding rate） | ❌ FalconX 是 Swap 模式（按持仓过夜次数收利息），无 funding rate |

> **修改建议区**（在此填写交易域需要修改的实现逻辑）：
>
> _修改：加入部分平仓的功能，用户可以进行部分平仓，释放保证金。_
> _修改：CROSS制作保留扩展功能，一期只做逐仓模式，不实现CROSS+ISOLATED 混合_
> _风控运营接口：一期提供管理端_

## §5 钱包域（wallet-service）

### 5.1 业务目标
基于 account-level xpub 的非硬化派生地址、链上扫块、入金确认、Outbox 投递

### 5.2 核心实体
| 表 | 字段语义 |
|----|---------|
| `t_wallet_address` | user_id, chain, token, network, address, derivation_path（uk_user_chain 唯一） |
| `t_wallet_deposit_tx` | wallet_tx_id, chain, tx_hash, log_index, from_address, to_address, amount, status(DETECTED/CONFIRMING/CONFIRMED/REVERSED) |
| `t_wallet_chain_cursor` | chain, cursor（最后扫块高度） |
| `t_outbox` | wallet.deposit.detected/confirmed/reversed 三事件 |

### 5.3 接口
| 端点 | 描述 |
|------|------|
| `POST /api/v1/wallet/deposit-addresses/ensure` | 进入入金页时幂等分配 TRC20 + ERC20 地址 |

### 5.4 关键实现
- **派生**：`XpubWalletAddressDerivationService`（BIP32 非硬化），不存私钥
- **链监听**：Web3J(ETH/BSC) + Solanaj(SOL) + Trident(TRX)
- **回调线程切换**：SDK 回调立即提交线程池（`AGENTS.md §3.8.2`）
- **ETH ERC20 优化**：`FX-057` 改为 `eth_getLogs` topic 过滤（避免逐 tx 拉 receipt）
- **Reversal**：cursor 重扫窗口内已 CONFIRMED 交易消失则发 `wallet.deposit.reversed`
- **wallet_tx_id**：跨服务唯一业务主键（trading-core 据此幂等入账）

### 5.5 已知缺口
- ❌ 无出金能力（钱包只做了入金）
- ❌ 入金最小金额规则（< 5 USDT 进 unmatched_transfer）未实现
- ❌ OFAC 名单接口未预留
- ❌ 注册后预分配未实现（依赖 identity → wallet 跨服务事件）

> **修改建议区**（在此填写钱包域需要修改的实现逻辑）：
> _修改：添加出金能力，首次出金或者更换非入金的钱包地址，需要提供KYC验证，KYC的规则按照上面的KYC规则来实现，简单的KYC，人工审核。_

## §7 前端（falconx-frontend）

### 7.1 业务域结构
| 域 | 内容 |
|----|------|
| `auth/` | 登录、注册、Token 管理、Refresh 单飞刷新 |
| `market/` | 行情列表、K 线图（lightweight-charts）、WebSocket 订阅、tick/quote 历史 |

## §8 关键算法与公式

### 8.1 保证金与强平价
```
ISOLATED:
  marginAmount = positionMargin（用户输入或追加后）
  notional = quantity × entry_price
  fee = notional × fee_rate
  liquidation_price (LONG) = entry_price - margin / quantity
  liquidation_price (SHORT) = entry_price + margin / quantity

CROSS:
  account_margin = Σ position_margin（CROSS 持仓）
  equity = account.balance + Σ unrealized_pnl
  cross_maintenance = Σ (entry × quantity × maintenance_margin_rate)
  触发：equity ≤ cross_maintenance
  选中：unrealized_pnl 最负的持仓优先平
```

### 8.2 已实现/未实现 PnL
```
unrealized_pnl (LONG) = quantity × (mark_price - entry_price)
unrealized_pnl (SHORT) = quantity × (entry_price - mark_price)
mark_price = LONG → bid / SHORT → ask（按 BUY/SELL 对应对手价）

realized_pnl 在平仓时计算并落 t_trade.realized_pnl
```

### 8.3 Swap 结算
```
每日 17:00 EST（每个时区可配）：
  rollover_swap = position.notional × symbol_swap_rate（按 long/short 区分）
  从 t_position.margin 扣（不动 t_account.balance）
  写 t_ledger biz_type=6/7（SWAP_INCOME/SWAP_EXPENSE）
```

### 8.4 负净值保护
```
强平结算时：
  net_settlement = current_margin + realized_pnl - close_fee
  if net_settlement < 0 → 账户余额扣到 margin 为止（不为负）
                          差额计入 t_liquidation_log.platform_covered_loss
```

## §9 跨域端到端流程（J1-J3）

### J1 注册 → 入金页地址
```
浏览器 → POST /api/v1/auth/register
  identity 创建 t_user (status=ACTIVE) + 签 JWT
  返回 userId/email/status
浏览器（带 JWT）→ POST /api/v1/wallet/deposit-addresses/ensure
  wallet 派生 TRC20 + ERC20 写 t_wallet_address
  返回 [{ chain:TRC20, address:T...}, { chain:ERC20, address:0x...}]
```

### J2 入金到账
```
用户从外部钱包转 USDT → 客户派生地址
wallet listener 扫块识别 (to_address ∈ t_wallet_address)
  → t_wallet_deposit_tx (status=DETECTED) → outbox (wallet.deposit.detected)
确认数达标
  → t_wallet_deposit_tx (status=CONFIRMED) → outbox (wallet.deposit.confirmed)
trading-core 消费 wallet.deposit.confirmed
  → 幂等检查（walletTxId）→ 事务内：t_account.balance += amount + t_ledger(DEPOSIT) + t_deposit
  → outbox (trading.deposit.credited)
identity 消费 trading.deposit.credited
  → t_inbox 留痕 + 若 legacy PENDING_DEPOSIT 用户则归一化为 ACTIVE
```

### J3 开仓 → 强平
```
浏览器 → POST /api/v1/trading/orders/market { symbol, side, quantity, leverage, marginMode }
  trading-core risk → ledger → position → trade → 推送
LP tick 持续推送 → market-service → Kafka price.tick
  → trading-core QuoteDrivenEngine 每 tick：
    ISOLATED 持仓评估 TP/SL/强平 → closePositionByPositionLevelTrigger
    CROSS 用户账户级评估 → closePositionByAccountLevelLiquidation
  → 平仓事务 → 推送 position.update / liquidation.update
```
