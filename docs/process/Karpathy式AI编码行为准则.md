# Karpathy 式 AI 编码行为准则

## 1. 目的

本文把 `forrestchang/andrej-karpathy-skills` 中的 AI 编码行为原则适配为 FalconX 项目规范，用于减少 AI 代理在编码、审查、重构和调试中的常见失误：

- 代替用户做未经确认的假设。
- 把简单需求实现成臃肿抽象。
- 顺手修改无关代码、注释或格式。
- 没有把任务转化为可验证的成功标准。

本文是 `AGENTS.md` 与 [AI协作与提示规范](./AI协作与提示规范.md) 的行为层补充，不替代 FalconX 的架构、接口、数据库、事件、安全、状态机、事务、日志、测试和完成定义。

## 2. 来源与适配边界

来源：

- GitHub: `forrestchang/andrej-karpathy-skills`
- 核心内容：Think Before Coding、Simplicity First、Surgical Changes、Goal-Driven Execution
- 许可证：MIT

适配边界：

- 若本文与 FalconX 正式规范冲突，以 `AGENTS.md`、`SKILLS.md` 和对应专题正式规范为准。
- 若本文与用户明确指令冲突，先按用户最新指令处理；但涉及 `API / DB / Kafka / WebSocket / 状态机 / 错误码 / owner / 安全 / 事务` 的契约变化仍必须先确认。
- 对 typo、单行文案、格式级局部修订，可按快速通道执行；但不得借快速通道修改业务语义。

## 3. 四条强制行为准则

### 3.1 编码前先澄清

开始实现前必须先说明当前理解和关键假设。若存在多种解释，不得静默选择其中一种直接编码。

必须执行：

1. 明确任务属于哪类修改：文档、前端、REST、WebSocket、DB、Kafka、缓存、状态机、安全、事务、测试或全栈对接。
2. 明确本轮需要读取的最小正式规范。
3. 对会影响契约或 owner 边界的决策先请求确认。
4. 发现更简单或风险更低的方案时，先说出权衡，再继续执行。
5. 发现需求、现有代码和正式规范互相矛盾时，停止扩写实现，先输出冲突点。

禁止行为：

- 不说明假设就直接改代码。
- 把“不确定”包装成确定结论。
- 在没有证据时把问题归因给某个模块或服务。

### 3.2 简洁优先

实现必须使用能满足当前需求的最小方案，优先复用现有模式，不为未来可能性提前设计抽象。

必须执行：

1. 只实现用户要求和正式规范要求的能力。
2. 单次使用的逻辑不得为了“可扩展”强行抽象。
3. 优先沿用当前包结构、组件模式、Repository / Mapper / Service 分层和前端 feature 组织方式。
4. 新增配置项、状态、错误码、事件字段或通用组件前，必须能说明实际复用边界。
5. 若实现明显可以缩小，先收缩实现再交付。

禁止行为：

- 添加用户未要求的功能。
- 为不存在的场景添加复杂兜底。
- 用新框架、新模式或平行设计系统绕过仓库现有约定。

### 3.3 精准修改

每一行修改都必须能追溯到用户请求、本轮缺陷或正式规范要求。

必须执行：

1. 只修改完成当前任务必须修改的文件。
2. 匹配既有代码风格，即使存在个人偏好的不同写法。
3. 只清理本轮改动产生的无用 import、变量、函数、测试夹具或文档引用。
4. 发现无关死代码、历史债务或可优化点时，只在结论中说明，不顺手删除。
5. 工作区存在无关改动时，先识别并隔离，禁止混入本轮提交。

禁止行为：

- 顺手重构没坏的代码。
- 顺手改相邻注释、格式、命名或目录结构。
- 回退用户或其他代理的无关改动。

### 3.4 目标驱动执行

任务必须转化为可验证目标，并循环到验证闭合后再声明完成。

必须执行：

1. 对非平凡任务给出简短计划，并为每一步写出验证方式。
2. 修 bug 时先找到根因；能补测试时，先补能复现问题的测试。
3. 重构前后必须保留行为证据，至少执行相关测试或构建检查。
4. 前端和三端业务任务必须包含浏览器、接口状态和响应式验证证据。
5. 交付结论必须明确已验证范围、未验证范围、剩余风险和使用方式。

禁止行为：

- 只说“应该可以”而不执行验证。
- 把没有运行的测试写成已通过。
- 用“开发阶段后补”跳过当前任务需要的文档、测试或回滚点。

## 4. FalconX 执行检查表

每次非平凡任务进入实现前，至少确认：

- 已读取 `SKILLS.md`。
- 已按任务类型读取最小正式规范。
- 已识别是否触及 `API / DB / Kafka / WebSocket / 状态机 / 错误码 / owner / 安全 / 事务`。
- 已说明关键假设或冲突点。
- 已限定修改范围。
- 已定义验证命令或浏览器验证方式。

每次交付前，至少确认：

- 变更范围没有超出用户请求。
- 没有无关重构或格式 churn。
- 测试、构建、浏览器验证或无法验证原因已经写清。
- 文档同步要求已经处理。
- Git 回滚点已经形成。

## 5. 与现有流程的关系

本文不新增独立工具链。它嵌入现有流程：

- `AGENTS.md`：仓库最高执行入口。
- `SKILLS.md`：编码任务的强制步骤模板。
- [AI协作与提示规范](./AI协作与提示规范.md)：决定最小阅读集、文档真源和验证深度。
- [AI工作模式](./AI工作模式.md)：决定 10 角色三端协作、派发、边界与完成判定。
- [完成定义](./完成定义.md)：决定任务能否声明完成。

执行顺序上，本文应在读取 `AGENTS.md` 与 `SKILLS.md` 后、进入具体实现前作为行为检查使用。
