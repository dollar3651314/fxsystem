### 1.3 数据访问规则

按 [`AI工作模式`](../process/AI工作模式.md) Console 特殊架构地位：

- **跨业务 schema 只读权限**：console DB user 拥有 `falconx_identity / falconx_market / falconx_trading / falconx_wallet` 的 SELECT 权限
- **写操作必须通过业务服务 internal RPC**（如冻结用户必须调用 `identity-service` 的 `/internal/v1/users/{id}/freeze`，不得直接 UPDATE）
- **console 只写自己 schema**：`falconx_console`（admin 用户/角色/权限/菜单/审计 5 类表）

## §2. RBAC 权限模型（用户 / 角色 / 菜单 / 按钮四级）

### 2.1 数据模型

```sql
-- 管理员账号
CREATE TABLE t_admin_user (
    id BIGINT PRIMARY KEY,
    username VARCHAR(64) UNIQUE,
    password_hash VARCHAR(255),
    real_name VARCHAR(64),
    status TINYINT,         -- 1=ACTIVE, 2=DISABLED
    last_login_at DATETIME(3),
    last_login_ip VARCHAR(64),
    created_at, updated_at
);

-- 角色
CREATE TABLE t_admin_role (
    id BIGINT PRIMARY KEY,
    code VARCHAR(64) UNIQUE,    -- 如 SUPER_ADMIN, FINANCE, KYC_REVIEWER
    name VARCHAR(64),           -- 显示名
    description TEXT,
    is_system TINYINT,          -- 1=系统内置（如 SUPER_ADMIN，不可删）
    created_at, updated_at
);

-- 权限点字典（由代码注解扫描生成）
CREATE TABLE t_admin_permission (
    id BIGINT PRIMARY KEY,
    code VARCHAR(128) UNIQUE,   -- 如 customer:view / customer:freeze / withdraw:approve
    module VARCHAR(64),         -- 如 customer / withdraw / kyc
    action VARCHAR(64),         -- view / create / update / delete / freeze / approve / ...
    description TEXT,
    created_at
);

-- 菜单
CREATE TABLE t_admin_menu (
    id BIGINT PRIMARY KEY,
    parent_id BIGINT,           -- 树形结构
    code VARCHAR(64) UNIQUE,
    name VARCHAR(64),
    icon VARCHAR(128),
    path VARCHAR(255),          -- 前端路由
    permission_code VARCHAR(128),  -- 该菜单需要的权限点
    sort INT,
    is_visible TINYINT,
    created_at, updated_at
);

-- 角色 ↔ 权限点
CREATE TABLE t_admin_role_permission (
    role_id BIGINT,
    permission_code VARCHAR(128),
    PRIMARY KEY (role_id, permission_code)
);

-- 管理员 ↔ 角色
CREATE TABLE t_admin_user_role (
    user_id BIGINT,
    role_id BIGINT,
    PRIMARY KEY (user_id, role_id)
);

-- 操作审计（按月分区，保留 7 年）
CREATE TABLE t_admin_operation_log (
    id BIGINT PRIMARY KEY,
    admin_user_id BIGINT,
    permission_code VARCHAR(128),  -- 操作类型
    target_type VARCHAR(64),        -- 操作目标类型（user / withdraw / symbol 等）
    target_id VARCHAR(128),         -- 操作目标 ID
    before_value JSON,              -- 操作前值
    after_value JSON,               -- 操作后值
    risk_level VARCHAR(16),         -- LOW / MEDIUM / HIGH_RISK
    ip VARCHAR(64),
    user_agent TEXT,
    occurred_at DATETIME(3)
) PARTITION BY RANGE COLUMNS(occurred_at);
```

格式：`{module}:{action}`

模块枚举（按管理后台业务分组，与 [`完成定义`](../process/完成定义.md) §4.A 三端要求中的管理端最小入口对齐）：

| module | 主要 action |
| --- | --- |
| customer | view, freeze, unfreeze, tag, balance:adjust, message |
| kyc | view, approve, reject |
| deposit | view, unmatched:view, reconciliation:view |
| withdraw | view, approve, reject, urgent-cancel |
| trading-monitor | order:view, position:view, exposure:view, manual-liquidate, auto-liquidate:pause |
| pending-order | view, force-cancel |
| price-alert | view, force-delete |
| symbol | view, source:create, source:update, suspend, swap-rate:update, quote-mapping:update, group-visibility:update（`update` 已废弃，R2 三轮拆为 `source:update`） |
| risk-action | view, activate, deactivate, audit:view |
| risk-market-config | view, update |
| system-config | view, update |
| announcement | view, create, update, delete |
| notification-template | view, create, update |
| audit | operation-log:view, login-log:view |
| admin-user | view, create, update, disable |
| admin-role | view, create, update, delete |
| admin-menu | view, create, update, delete |

### 2.3 权限点埋点（R9 强制）

```java
@RestController
@RequestMapping("/api/v1/admin/customer")
public class AdminCustomerController {

    @PostMapping("/{userId}/freeze")
    @RequiresPermission("customer:freeze")
    public ApiResponse<Void> freeze(@PathVariable Long userId, @RequestBody FreezeRequest req) {
        // ...
    }
}
```

启动时扫描 `@RequiresPermission` 注解 → 同步到 `t_admin_permission` 字典。

### 2.4 前端按钮级控制（R10 强制）

```tsx
<RequiresPermission code="customer:freeze">
  <Button onClick={onFreeze}>冻结账户</Button>
</RequiresPermission>
```

权限码集合从 `GET /api/v1/admin/me/permissions` 加载到全局 store。菜单按权限过滤（用户只看自己有权访问的菜单项）。

## §3. 鉴权架构

### 3.1 admin JWT

- **独立私钥**（与 C 端 JWT 完全隔离，避免 token 复用风险）
- payload：`sub(adminUserId) / username / roles[] / iat / exp / jti`
- 过期时间：access 30 分钟，refresh 8 小时（比 C 端短）
- jti 加 Redis 黑名单支持登出

### 3.2 IP 白名单（双层）

- **gateway 路由级**：`/admin/*` 路由前置 IP 白名单 filter（仅允许办公网 / VPN IP）
- **console-service 应用级**：再次校验 IP（应对 gateway 配置错误时的兜底）

### 3.3 高风险操作二次确认（R10 强制）

**真源**：[`docs/design/admin高危操作风控档位.md`](../design/admin高危操作风控档位.md)（2026-05-19 收口 8 项）

清单 / 三重门规则（reason ≥10 + 用户名挑战 + confirm checkbox）/ 错误码兜底 / 单测规范全部以真源文档为准。
**新增「直接动钱 / 平台级风控开关」类操作时必须先在真源文档 §2 登记**，并接入
`HighRiskConfirmModal`（`falconx-console-frontend/src/features/customer/HighRiskConfirmModal.tsx`），禁止再造裸 `<Modal>`。

## §4. 跨服务调用规则

### 4.1 业务服务暴露 internal API

每个业务服务暴露 `/internal/v1/*` 路径，仅接受来自 console-service 的调用。

**鉴权方式：gateway 内部 token（静态配置 + 手动轮换，用户决策于 2026-05-09）**

具体机制：

1. **token 来源**：环境变量 `FALCONX_INTERNAL_API_TOKEN`（部署运维配置，所有业务服务 + console-service 必须使用同一值）
   - dev profile 默认值：`falconx-internal-dev-token`（仅 dev/test，禁止 prod 使用）
   - prod / staging 必须显式设置环境变量；缺失时服务启动失败（fail-closed）

2. **header 名**：`X-Internal-Token`（自定义 header，避免与 `Authorization` 冲突）

3. **gateway 注入**：当请求路径匹配 `/internal/v1/**` 时，gateway 自动注入 `X-Internal-Token`。客户端无法直接命中此路径（gateway 路由规则配置 `predicate: Path=/internal/v1/**` + `filter: SetRequestHeader=X-Internal-Token,${FALCONX_INTERNAL_API_TOKEN}`）

4. **业务服务校验**：identity-service / market-service / trading-core-service / wallet-service 各自实现 `InternalApiTokenFilter`：
   - 拦截 `/internal/v1/**` 路径
   - 比对 `X-Internal-Token` 是否等于本服务读到的 `FALCONX_INTERNAL_API_TOKEN`
   - 不匹配 → HTTP 401，业务错误码 `90701` `INTERNAL_TOKEN_INVALID`
   - 缺失 header → HTTP 401，业务错误码 `90702` `INTERNAL_TOKEN_MISSING`

5. **拒绝直连**：业务服务在生产网络拓扑层面应通过 firewall / k8s NetworkPolicy 限制 `/internal/v1/**` 仅接受来自 gateway 的请求（应用层 filter 是兜底；网络层是主防线，由运维配置）

6. **轮换策略（一期手动）**：运维同步更新所有服务的环境变量 → 滚动重启所有业务服务 + console-service + gateway。轮换期间 console 调用 internal API 会出现短暂 401，由 R9 调用方做有限重试（3 次 + 指数退避）。一期不进入自动轮换。

7. **不进入 V2 范围**：自动轮换 + 双 token 平滑过渡 + KMS 集成属于阶段 11 可观测性 + Secret 管理范围。

**调用方上下文 header**（由 console-service 注入）：

- `X-Internal-Token`（gateway 注入）
- `X-Admin-User-Id`（调用发起人，business-service 不校验权限，仅记录用于审计追溯）
- `X-Trace-Id`（链路追踪）

**业务服务职责**：

- 校验 `X-Internal-Token` 合法性
- 执行业务操作（按 internal RPC 契约）
- 返回结果（不写管理操作审计；审计由 console 负责）
- 业务自身的领域审计（如 identity 的登录历史）按业务原有规范执行

### 4.2 console 写审计

console 调用业务 internal API 后，必须立即写 `t_admin_operation_log`：

- 包含 admin_user_id（哪个管理员发起）
- permission_code（哪个权限点）
- target_type + target_id（操作了什么）
- before_value + after_value（如调余额需要前后值）
- risk_level（HIGH_RISK 标记需要月底 review）

### 4.3 跨 schema 只读查询规则

console 直接 SELECT 业务 schema 表用于：

- 列表展示（如客户列表，跨 identity + trading 拼装余额）
- 详情查询（如订单详情，跨 trading 多表 join）
- 报表统计（如净敞口看板）

**严禁**：
- INSERT / UPDATE / DELETE 业务表
- 业务事务内调用业务表（破坏事务边界）
- **trading-core 跨 schema 直查 `falconx_market`**：trading-core 的下单 / 强平 / 保证金 / 费率读取**禁止** SELECT `falconx_market.t_symbol_quote_mapping`；必须通过 Redis Hash `falconx:market:symbol-spec:{platformSymbol}` 消费 market 暴露的 `SymbolSpec`（owner 在 market-service）。R2 三轮 STAGE-2-SYMBOL-PARAMS-DOWNSHIFT 实施完成后这条强制约束生效；当前 trading-core 不读 t_symbol，是退化的等价边界

### 4.4 调余额限额（Redis 实时限额 + 审计留痕，用户决策于 2026-05-09）

`customer:balance:adjust` 操作的限额：

- 单次 ≤ $5000
- 单日 ≤ $20000（按 UTC 自然日 00:00-24:00 计）

**实现**：

1. **Redis 滑动窗口（实时校验，快路径）**
   - key: `falconx:admin:balance-adjust:daily:{adminUserId}:{yyyyMMdd-UTC}`
   - TTL: 25h（覆盖 UTC 自然日 + 1h buffer）
   - 写时序：操作前 `INCRBY <amount-cents>`，超过 $20000 阈值则回退（`DECRBY`）+ 拒绝
   - 单次操作金额预校验：>$5000 直接拒绝，不写 Redis

2. **DB 审计表（持久化留痕）**
   - 复用 `t_admin_operation_log`（permission_code='customer:balance:adjust'）
   - `before_value`/`after_value` 用 JSON 存调整前后金额
   - 审计仅用于事后追溯，不作为 Redis 不可用时的实时限额兜底

3. **冲突处理**：Redis 计数不可用时直接拒绝调余额并返回 5xx，避免高风险资金操作在限额不可判定时 fail-open；操作未进入 trading-core，不写业务账本

错误码：

- `90301` `ADMIN_BALANCE_ADJUST_SINGLE_LIMIT_EXCEEDED`（单次超 $5000）
- `90302` `ADMIN_BALANCE_ADJUST_DAILY_LIMIT_EXCEEDED`（单日累计超 $20000）
- Redis 计数不可用：返回系统内部错误（`99xxx` 系统级错误码），不得继续执行调余额

## §5. 前端架构（falconx-console-frontend）

### 5.1 技术栈

- Vite + React + TypeScript（与 C 端一致）
- React Query + Zustand（状态管理）
- React Router（路由）
- Ant Design（管理后台 UI 库 — **唯一允许的新 UI 框架**，仅用于管理端，不引入 C 端）

### 5.2 目录结构

```
falconx-console-frontend/
  src/
    components/         # 通用组件（含 RequiresPermission）
    features/
      auth/             # 登录 / 重置密码 / token 管理
      dashboard/        # 总览看板
      customer/         # 客户管理
      kyc/              # KYC 审核
      deposit/          # 入金管理
      withdraw/         # 出金审核
      trading/          # 交易监控
      pending-order/    # 挂单监控
      price-alert/      # 价格告警监控
      symbol/           # 行情品种管理
      risk/             # 风控管理
      system/           # 系统配置
      notification/     # 通知模板
      audit/            # 审计查询
      admin-user/       # 管理员账号
      admin-role/       # 角色管理
      admin-menu/       # 菜单管理
    layouts/            # 后台主布局
    lib/                # api client / config / permission
    providers/
    styles/             # tokens（与 C 端共用基础 token + 管理端扩展）
```

### 5.3 与 C 端 token 的关系

- 共用：`tokens.css` 中的 颜色 / 字体 / 间距基础 token
- 扩展：管理端特有的 token（如表格密度、Form 间距等）单独定义

## §6. 部署边界

- console-service 与业务服务完全隔离（独立进程、独立配置、独立日志）
- console-frontend 独立部署到管理端域名（如 `admin.falconx.internal`）
- gateway 通过 path 路由 `/admin/*` 到 console-service
- 一期不强制 console 多实例 HA（管理后台访问量低，单实例即可）
